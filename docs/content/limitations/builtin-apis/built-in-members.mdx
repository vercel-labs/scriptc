- **Built-in members:** Replacing or deleting an existing member of one of the language's built-in objects is refused at build time, a deliberate difference from Node.js.
  Compiled code calls a built-in such as `Array.prototype.push` or `Math.random` directly and never reads it from its object, so a replacement would not run.
  A write the build can see is refused with `SC1092`: an assignment, `delete`, `Object.defineProperty`, `Object.defineProperties`, `Object.assign`, or a `Reflect` call whose target is a built-in constructor, its `prototype`, `Math`, `JSON`, `Reflect`, or the global object.
  The refusal applies to TypeScript and JavaScript sources alike, and covers a member the object inherits from another built-in.
  A polyfill guarded by a test of the member, such as `if (!Array.prototype.at) { ... }`, compiles: the member exists in Node 24, so the guarded code never runs.
  Adding a member the object does not have, redefining a member with the same value to change its attributes, and assigning `Error.stackTraceLimit` are not refused.
  A write the build cannot see, where the object or the key arrives as a value, is not refused: `Math`, `JSON` and `Reflect` members throw at run time, and for other built-ins compiled code keeps calling the built-in.
  To change what a built-in does, for a test mock for instance, call a function of your own and replace that.
  A package that contains such a write runs in a Node island under the default `--node-islands=auto`.
