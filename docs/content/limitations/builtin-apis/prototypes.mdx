- **Prototypes:** Named properties and methods on program class prototypes support replacement, inheritance, and deletion.
  A module-level class's prototype can become the prototype of other objects: `Object.create(C.prototype)`, `Object.setPrototypeOf(F.prototype, C.prototype)`, `Object.setPrototypeOf(object, C.prototype)`, and `util.inherits(F, C)` with an ordinary constructor `F`.
  The inherited methods and accessors run with the inheriting object as `this`.
  Methods that use `#private` members or `super` throw a TypeError for a receiver that is not an instance of the class, and so does a TypeScript member whose signature cannot lower as a value; other methods and accessors run on an object made with `Object.create(C.prototype)`, and `Object.create(C.prototype) as C` keeps the created object, whose absent fields read `undefined`.
  Inside a TypeScript member run over such an object, an absent number field is NaN in arithmetic, and interpolating it into a string prints `NaN` where Node prints `undefined`.
  `C.prototype` also reads as a value wherever it is only read: `Object.getPrototypeOf`, `Object.getOwnPropertyDescriptor`, `Object.getOwnPropertyNames`, `Object.keys`, `Reflect.ownKeys`, `Reflect.has`, `typeof`, `in`, `===` and `!==`, and a `const` bound to it whose every use is one of these or a member read or call; its methods and accessors are its own properties, with Node's descriptors.
  A declared accessor can be replaced through the prototype: `Object.defineProperty(C.prototype, "x", descriptor)`, `Reflect.defineProperty` and `Object.defineProperties` replace it for every instance and for objects made from the prototype, and an assignment or read of it through `C.prototype` itself runs the setter or getter with the prototype object as `this`, as Node does.
  Changing the prototype of a class prototype (`Object.setPrototypeOf(C.prototype, X)`, `util.inherits(C, F)`, or `Object.setPrototypeOf` on a class prototype reached through an instance) is unsupported.
  Other bare prototype reflection (a binding written to, or passed where it may be changed), and prototype storage on local, generic, mixin, or runtime-provided classes are unsupported.
  Plain objects, arrays, functions, class instances, and Date, RegExp, Map, Set, WeakMap, WeakSet, and Promise values inherit `constructor`, `valueOf`, `toString`, `hasOwnProperty`, and `propertyIsEnumerable` from `Object.prototype` as in Node, so `value.constructor === Object` and `value.valueOf === Object.prototype.valueOf` compare identities exactly.
  Named reads such as `value.valueOf` answer these inherited members; computed-key reads such as `value[key]` do not.
  In a TypeScript source, `instance.constructor` on an instance of a program class is the instance's own class, whatever class the static type names.
  Its `name`, comparisons with a class, `new (this.constructor as typeof C)(...)`, and statics read or called through `(this.constructor as typeof C).member` answer as in Node.
  The constructor of a generic class's instance answers its `name` only, and `constructor` is unsupported in a hierarchy that includes a function-local class extending another function-local class.
  Binding `this.constructor as typeof C` to a variable is unsupported when a subclass takes different constructor arguments, and so is `constructor` read through the static type of an array, Map, Set, function, or builtin error.
  Static accessors of TypeScript classes compile, including inherited ones and `super` in a static member; compound assignment and `++` on a static accessor are unsupported.
  `Object.prototype`'s own members read as values; its mutation and other reflection, such as `isPrototypeOf` and `__proto__`, are unsupported.
  In a JavaScript source, `Date.prototype` and `ArrayBuffer.prototype` read as the prototype objects the language defines — an ordinary object carrying the interface's members and constructor, with ArrayBuffer's `byteLength`, `maxByteLength`, `resizable` and `detached` as getters — so existence tests such as `Object.prototype.hasOwnProperty.call(ArrayBuffer.prototype, "detached")` answer as in Node, and a method called on the prototype object itself throws a TypeError.
  ArrayBuffer's prototype getters and methods brand-check an ArrayBuffer receiver, so one run on a SharedArrayBuffer or any other value throws the TypeError Node throws.
  The constructors `Object`, `Function`, `Date`, `RegExp`, `Map`, `Set`, `WeakMap`, `WeakSet`, and `Promise` read as function values; through a stored value only `Object` and `RegExp` can be called.
  A stored `RegExp` call builds what `new RegExp(...)` builds, except that a pattern that is a RegExp is answered itself when no flags are passed, as in Node.
  `new` through a stored `Object`, `Date`, `RegExp`, `Map`, `Set`, `WeakMap`, or `WeakSet` builds the same value as the `new` expression.
  `new` through a stored `Promise`, `new` of a stored `Object` with a primitive argument, and `instanceof` against these constructors are unsupported.
  `instanceof Object` and `instanceof Function` on untyped values follow the prototype chain as in Node, so an object built with `Object.create(null)` is not an `Object`.
