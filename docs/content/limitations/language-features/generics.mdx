- **Generics:** Generic functions declared inside other functions, generic class expressions, and generic methods requiring dynamic dispatch are unsupported.
  Generic classes can extend generic bases when each specialization has a concrete layout.
  A generic class used as a value without type arguments, such as `{ Box }` or a `typeof Box` parameter, is one class whose type parameters hold checked-dynamic values, and `instanceof` through it answers for every specialization.
  A typed construction through such a value whose type arguments infer to anything else, such as a default `T = string`, is unsupported.
  Two instantiation expressions such as `Box<number>` and `Box<string>` are different values, where Node.js has one class.
  Independent concrete uses have no specialization-count limit; recursively expanding demands and type layouts produce diagnostics.
  Other generic calls compile when the target resolves statically.
  Generic generator methods, sync and async, compile like other generic methods.
  A generic async generator method called through an untyped value, or through an interface whose receiver's class the compiler does not know, throws a coded SC2020 error.
  Generic function values require a concrete signature at use and a binding that is never reassigned.
  Inside a generic instance whose binding holds values of several record layouts, a statement that takes the binding's value as the one record type its constraint names (an argument for a parameter of that type, a function literal's parameter, or a destructuring pattern) builds with warning `SC6015` and throws a `TypeError` when it runs with a value of another layout, where Node completes it.
- **Variadic wrappers:** A generic higher-order wrapper is specialized to each wrapped function's exact signature.
  `Parameters<F>`, `ReturnType<F>`, and rest parameters typed as fixed tuples become that signature's parameter list.
  A function expression with no parameters that reads `arguments` compiles only when its value is asserted to, or contextually typed as, one fixed-arity signature; `arguments` is then that signature's tuple.
  Forwarding it with `fn.apply(this, arguments)` passes `this` through.
  Reading `fn.name` on a wrapped function requires its name to be known where the wrapper is called, such as a function declaration or a `const`-bound function.
  `Parameters<F>` over a signature with optional or array-typed rest parameters is unsupported, because that tuple has no fixed length.
