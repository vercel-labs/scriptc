Native code cannot run JavaScript source at runtime, because code that scriptc compiles carries no JavaScript engine.
In your program's own code and in packages compiled natively, `eval`, indirect `eval`, `new Function`, and `Function` behave as they do under `node --disallow-code-generation-from-strings`, a deliberate difference from default Node.js: every call throws a catchable `EvalError` with the message `Code generation from strings disallowed for this context`.
The arguments are evaluated first, and the Function constructor converts them to strings before it throws, as Node.js does.
Packages that test for code generation before using it, such as zod 4, take their interpreted path.
An npm package that builds code from strings without such a test runs in a [Node island](/docs/node-islands), where Node.js evaluates the source as usual.
Your own code that needs to evaluate source at runtime must be rewritten; to compute a value from code at build time, use `comptime`.
The `vm` module is refused in your own code for the same reason.
See [npm Dependencies](/docs/dependencies#which-packages-compile) for which packages compile.
