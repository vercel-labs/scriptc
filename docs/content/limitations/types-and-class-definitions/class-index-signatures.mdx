- **Class index signatures:** A class may declare `[key: string]: any` or `[key: string]: unknown`.
  The signature takes no storage: a name the class does not declare is an own property of the instance, absent until something assigns it, as in Node.js.
  Reads, assignments, computed keys, `in`, `Object.keys`, `JSON.stringify` and untyped views of the instance see the same property.
  An instance lists its declared fields before the added properties, which differs from Node.js only when a field initializer adds a property before a later field is defined.
  A signature with another value type or a number key is refused.
  A subclass of such a class cannot declare instance fields of its own; declare them in the class that has the signature, or assign them through it.
  Assigning a declared field through a computed key checks the value against the field's type and throws a `TypeError` on a mismatch, where Node.js stores the value.
  Compound assignment, `++`, `--`, `delete` and method calls on a name the signature admits, and object spread of the instance, are refused.
